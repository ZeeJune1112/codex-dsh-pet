# 按会话隔离并以尽力而为方式消费 Hooks

用户已确认：桌宠宿主按需启动，事件适配器按 `session_id` 自动创建或绑定桌宠实例；每个实例只反馈一个 Codex 会话，重新绑定必须是显式管理操作。Hooks 只接收并转发白名单状态字段，不持久化聊天正文、工具参数、工具结果或 transcript，也不返回会阻塞、批准、拒绝或追加上下文的控制性输出。

状态反馈按绑定会话独立聚合并保留上游表现优先级。由于异步 Hooks 可能乱序、丢失或在会话结束时取消，事件联动采用尽力而为语义：不能可靠判断时显示未知；`PermissionRequest` 不代表权限已解除；`Stop` 不代表成功；`Interrupt` 只在收到时表示中断。Hooks 的断线、重启或缺失事件不得阻塞 Codex。

首个平台验收范围为 Windows 11 x64。桌宠宿主负责窗口、进程、断线和退出清理；关闭单个宠物只隐藏该实例，退出宿主需要明确操作。`SessionEnd` 只在实际收到时用于结束会话，不能把聊天焦点变化当作结束。
