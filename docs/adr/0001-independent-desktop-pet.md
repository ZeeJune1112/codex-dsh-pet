# 通过独立桌宠窗口联动 Codex

依据用户已经明确的迁移边界，首个平台为 Windows，采用独立桌宠窗口与 Codex 联动，保留 dsh-pet 的角色素材、动画、桌面交互、状态反馈和管理能力。此选择基于目前已核查的 Codex 原生 Pet 自定义接口仅支持素材包这一前提；该接口的实际能力仍需以来源和验证记录补充，不能据此宣称 Hooks 的事件语义已经得到验证。

为了持续同步上游，尽量保留上游结构，将 Codex 特有改动集中在宿主启动、事件适配和生命周期管理，并记录确定的上游版本及本地补丁。独立窗口会增加进程和窗口生命周期管理成本，但允许保留完整桌宠体验；不以重新设计宠物或单一文字测试宠物替代迁移目标。

Hooks 已选为事件来源，其按会话隔离、轮次保守处理、尽力而为投递和生命周期规则由 ADR 0002/0003 记录。联动不额外调用模型，不保存聊天正文、工具参数或结果，启用 Hooks 遵循原生审核流程。包装器在硬截止时间内静默失败退出；真实原生投递和权限等待后续事件仍需验收，不把公开契约或合成测试当作实际验证。

代码复用保留上游 MIT 版权及许可声明；角色素材和原生依赖的授权分别核查。演示角色、外部导入角色和上游自带素材的存在，均不能单独作为再分发授权的证明。

## 当前核查记录

上游基线已固定为 `ysyyhhh/dsh-pet@a17346b9c41efb4220f387216008928bba652e0e`。该版本已经是 Windows 优先的 Node/Win32 实现，核心的标准化事件、状态机、渲染器和素材契约作为迁移基础；独立宿主、会话事件适配和本地管理页补充 Codex 入口，保留上游插件入口。

该基线的多宠窗口回调、等待解除、`alwaysOnTop`、`animationSpeed` 和导入信任边界已有本地修补，见 [上游补丁记录](../upstream-sync.md)。这些缺陷不作为必须复刻的行为；实际桌面交互验收与自动化边界测试分别记录。

官方 Hooks 文档确认了 `session_id`、轮次级 `turn_id`、异步执行限制、`PermissionRequest`、`Interrupt` 和 `SessionEnd` 的公开契约，但没有确认本机实际投递、权限解除事件或可靠的有序事件流。文档事实不等于本项目已完成运行验证。
