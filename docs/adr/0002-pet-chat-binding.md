# 每个桌宠实例绑定一个聊天

用户已确认：每个桌宠实例明确绑定一个 Codex 聊天，只反馈该聊天的工作状态，其他聊天的事件不能抢占它。保留多宠能力，同时观察多个聊天时可分别绑定不同实例；切换聊天焦点不会自动改变绑定。

该规则避免并发聊天的执行、权限等待和完成事件相互覆盖，代价是需要明确管理实例与聊天的对应关系。已选规则是：首次收到可接受的 `session_id` 事件时绑定一个未绑定实例，全部已绑定则创建使用默认角色的独立实例；重新绑定或解绑只能由管理页显式操作。绑定随设置持久化，宿主重启后反馈为未知，实际收到 `SessionEnd` 才进入结束状态并保留实例。事件来源的真实可靠性仍待原生 Hooks 验收；本决策不等于事件投递已实测。
